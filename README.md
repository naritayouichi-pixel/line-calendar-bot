# LINE × Googleカレンダー 予約Bot(店舗・固定シフト・予約登録・スタッフ通知対応)

LINE公式アカウントで店舗・日付・スタッフ・時間を選ぶと、Googleカレンダーに予約を自動登録し、
担当スタッフにLINEで通知するシステムです。

## 全体の流れ

1. ユーザーが「予約」ボタン(リッチメニュー)を押す
2. Botが「店舗を選ぶ」カード(ロゴ画像付き)を返信(自由が丘店 / 元住吉店)
3. ユーザーが店舗を選択 → Botが「日付を選ぶ」ボタン(LINE標準のカレンダーUI)を返信
4. ユーザーが日付を選択 → `src/shiftSchedule.js` の固定シフトから、その店舗・その曜日に
   出勤しているスタッフだけを自動で絞り込んで表示(顔写真付きカード。定休日ならその旨を返信)
5. ユーザーがスタッフを選択 → そのスタッフの勤務時間帯の中で、
   Google Calendar APIの `freebusy.query` を使い、Googleカレンダーの予定を差し引いた上で
   予約可能な開始時刻をボタンで提示
6. ユーザーが開始時刻を選択 → お名前の入力を依頼
7. お名前が入力されたら、Google Calendar APIの `events.insert` でそのスタッフのカレンダーに
   予約を登録し、お客様には確定メッセージ、担当スタッフにはLINEで通知を送信

## 事前準備

### 1. LINE Developersでチャネルを作成

1. https://developers.line.biz/console/ にログイン
2. プロバイダーを作成 → 「Messaging API」チャネルを作成
3. チャネル基本設定から以下を取得
   - **Channel secret**
4. Messaging API設定タブから以下を発行
   - **チャネルアクセストークン(長期)**
5. 同じ画面で「Webhookの利用」を **ON** にする
6. 「応答メッセージ」は **OFF**、「Webhook」は **ON** にしておく
   (これをしないとLINEの自動応答とBotの返信が二重になります)

### 2. Googleカレンダー側の準備

1. Google Cloud Console でプロジェクトを作成
2. 「Google Calendar API」を有効化
3. 「IAMと管理」→「サービスアカウント」でサービスアカウントを作成(1つでOK。全スタッフのカレンダーをこの1つのサービスアカウントに共有する)
4. 作成したサービスアカウントの「鍵」タブからJSON形式の鍵を作成・ダウンロード
5. **スタッフごとに**、確認したいGoogleカレンダー(そのスタッフの個人予定用カレンダー)の
   「設定と共有」を開き、サービスアカウントのメールアドレス
   (例: `xxx@xxx.iam.gserviceaccount.com`)を
   **「予定の変更権限」以上の権限**で共有に追加してください。
   - このBotは空き状況の確認だけでなく、予約をカレンダーに**書き込む**ため、
     「予定の表示」権限だけでは動作しません。必ず「予定の変更権限」(またはそれ以上)を選んでください。
6. ダウンロードしたJSON鍵をBase64化する

   ```bash
   cat service-account-key.json | base64 -w 0
   ```

   出力された文字列を `.env` の `GOOGLE_SERVICE_ACCOUNT_KEY_BASE64` に設定します。

7. `.env` の `STAFF_LIST` に、スタッフごとの `id:表示名:カレンダーID:LINEユーザーID` をカンマ区切りで設定します。

   ```
   STAFF_LIST=narita:成田:narita.youichi@gmail.com:U1234...,furuya:古屋:furuya@example.com:,ando:安藤:ando@example.com:
   ```

   - `id` は英数字のみ(`src/shiftSchedule.js` のシフト定義と一致させる必要があるので、
     そちらを変更しない限りは `narita` / `furuya` / `ando` のままにしてください)
   - `表示名` はLINE上に表示される名前(日本語OK)
   - `カレンダーID` はそのスタッフのGoogleカレンダーID
   - `LINEユーザーID` は予約通知を送る先。**省略可**(空のままでもエラーにはならず、
     その場合はそのスタッフへの通知だけ行われない)。取得方法は次のセクション参照。

### LINEユーザーIDの取得方法(スタッフへの予約通知に必要)

1. 通知を受け取りたいスタッフに、このLINE公式アカウントを友だち追加してもらう
2. そのスタッフから、トーク画面で

   ```
   ID確認
   ```

   と送ってもらう
3. Botが「あなたのLINEユーザーIDは以下です」というメッセージとともに、
   `U`で始まる長い文字列を返信するので、それをコピーして`.env`の`STAFF_LIST`に設定する

### 3. 環境変数の設定

`.env.example` を `.env` にコピーし、値を埋めてください。

```bash
cp .env.example .env
```

## 固定シフトの設定(店舗・曜日ごとの出勤スタッフ)

シフトは `src/shiftSchedule.js` に直接書かれています。曜日固定のシフトなので、
毎回スプレッドシートやカレンダーを更新する必要はありません。
シフトパターンが変わったときだけ、このファイルを編集してサーバーを再起動してください。

現在設定されている内容:

**自由が丘店**(火曜定休)
| スタッフ | 曜日 | 時間 |
|---|---|---|
| 成田 | 月・水 | 終日 |
| 成田 | 金 | 9:00〜16:00 |
| 成田 | 土 | 9:00〜19:00 |
| 安藤 | 水 | 16:00〜21:00 |
| 安藤 | 土 | 9:00〜13:00 |
| 古屋 | 木 | 終日 |
| 古屋 | 日 | 9:00〜17:00 |

**元住吉店**(火曜定休)
| スタッフ | 曜日 | 時間 |
|---|---|---|
| 古屋 | 月 | 終日 |
| 古屋 | 水 | 終日(13:00〜16:00は研修のため予約不可) |
| 古屋 | 土 | 9:00〜20:00 |
| 古屋 | 日 | 18:00〜20:00 |
| 安藤 | 木 | 終日 |
| 安藤 | 日 | 9:00〜14:00 |
| 成田 | 金 | 18:00〜22:00 |

水曜日は研修のため、自由が丘店の成田さんは14:00〜16:00、元住吉店の古屋さんは
13:00〜16:00の時間帯がそれぞれ予約不可になっています(下記の「飛び飛びのシフト」機能で対応)。

「終日」と設定されているシフトは、`.env` の `BUSINESS_HOUR_START` /
`BUSINESS_HOUR_END`(デフォルト9:00〜18:00)を勤務時間として扱います。

### シフトを変更したい場合

`src/shiftSchedule.js` の `SCHEDULE` オブジェクトを直接編集してください。

```js
wed: [
  { staffId: 'narita', start: null, end: null },       // 終日勤務
  { staffId: 'ando', start: '16:00', end: '21:00' },   // 時間指定あり
],
```

- `staffId` は `.env` の `STAFF_LIST` で設定したidと一致させる
- `start`/`end` を `null` にすると「終日勤務」扱いになる
- 定休日は `closedWeekdays: ['tue']` のように曜日キー(`mon`〜`sun`)を追加する
- 店舗を増やしたい場合は、`STORES` 配列に `{ id, name }` を追加し、
  `SCHEDULE` にもその店舗のキーを追加してください

### 飛び飛びのシフト(研修等で日中に予約不可の時間帯がある場合)

同じスタッフが同じ日に「途中で予約を受け付けない時間帯」を挟んで働く場合は、
同じ`staffId`のエントリを2つに分けて書きます。

```js
wed: [
  // 例: 水曜研修のため14:00〜16:00は予約不可
  { staffId: 'narita', start: BUSINESS_START, end: '14:00' },
  { staffId: 'narita', start: '16:00', end: BUSINESS_END },
],
```

`BUSINESS_START` / `BUSINESS_END` は、ファイル冒頭で `.env` の
`BUSINESS_HOUR_START` / `BUSINESS_HOUR_END` から自動的に計算される定数です。
LINE上では、このスタッフは1人分のカードとして表示され、
時間帯の選択肢には14:00〜16:00の間の枠だけが自動的に除外されます。

## 予約・予約確認できる期間

`.env` の `MAX_DAYS_AHEAD` で、今日から何日先まで予約・予約確認の対象にするかを設定します
(デフォルトは30日 = 約1ヶ月)。

```
MAX_DAYS_AHEAD=30
```

- 新規予約で選べる日付は「明日」から「今日+`MAX_DAYS_AHEAD`日」まで
- 「予約確認」で表示される予約一覧も、同じく「今日+`MAX_DAYS_AHEAD`日」以内のものだけに絞られます
  (それより先の予約がもしあっても、一覧には出てきません)

## チケット会員の予約制限(購入枚数分だけ予約可能)

チケットを購入したお客様(回数券のようなイメージ)は、**残っているチケットの枚数分だけ**
新規予約ができるようになります。月会費メンバーとは独立した、別のお客様区分です。

### 販売しているチケットの種類

チケットは「45分」「60分」の2種類、それぞれ「1回・5回・10回」の合計6パッケージのみです。

- 45分×1回
- 60分×1回
- 45分×5回
- 60分×5回
- 45分×10回
- 60分×10回

### 仕組み

- チケットは「予約した時点」ではなく、**実際に来店した時**に1枚消費されます
  (予約しただけでは減りません。来店確認は後述の方法でスタッフが行います)
- そのため、「まだ来店確認していない、確定済みの予約件数」が「残りチケット枚数」に達すると、
  それ以上の新規予約はできなくなります(残数がある限り、複数の日程を先に予約しておくことも可能です)
- **予約時に45分/60分を選ぶ必要はありません。** お客様が持っているチケットの種類に応じて、
  自動的にその長さで予約が作られます(45分チケットの残数があれば45分、なければ60分を使う形。
  お客様は基本的にどちらか1種類のみ持っている想定です。両方の残数がある場合は45分を優先します)
- **チケット会員は、予約できる日付に上限がありません。**(通常のお客様は`MAX_DAYS_AHEAD`
  日先までしか予約できませんが、チケット会員はそれよりずっと先の日付まで選べます。
  技術的な都合上、実際には`.env`の`TICKET_MAX_DAYS_AHEAD`(デフォルト90日)が上限になりますが、
  これは日付選択のボタンが並びすぎて表示が崩れないようにするための実用上の上限であり、
  通常の予約可能期間より十分長く設定しているため、事実上「無制限」として運用できます)
- 月会費メンバーでもチケット会員でもないお客様(ビジター等)には、この制限はかからず、
  今まで通り固定の時間(`BOOKING_DURATION_MINUTES`、デフォルト60分)・
  通常の予約可能期間(`MAX_DAYS_AHEAD`)で予約できます

### チケットの付与方法(管理者のみ)

`.env` の `ADMIN_USER_IDS` に、チケットを付与できる人(オーナー等)のLINEユーザーIDを設定します。

```
ADMIN_USER_IDS=U1234...
```

(複数人いる場合はカンマ区切りで指定してください。LINEユーザーIDの取得方法は
スタッフ・メンバー登録と同じく「ID確認」を参照)

管理者がLINEで

```
チケット追加
```

と送ると、まず6つのパッケージ(45分×1回、60分×1回…)がボタンで表示されます。

1. 追加したいパッケージのボタンをタップする
2. 「対象のお客様のLINEユーザーIDを送ってください」→ お客様のIDを送る
3. 「◯分チケットを◯枚追加しました。現在の◯分チケット残数: ◯枚」と表示されれば完了

お客様自身も、LINEで

```
チケット残数確認
```

と送ると、45分・60分それぞれの現在の残数を確認できます。

### お客様自身によるチケット購入(会員種別メニュー経由)

お客様が「会員種別」メニュー→「**チケット購入及び残数確認**」を選ぶと、
現在の残数(45分・60分それぞれ)が表示された後、6つのパッケージがボタンで表示され、
**その場で自分の残数に追加(自己申告制)**できます。

- 管理者向けの「チケット追加」と違い、LINEユーザーIDの入力は不要です
  (自分自身の残数にそのまま追加されます)
- 何度でも購入できます(月会費メンバーのコース登録と違い、一度きりではありません)
- 購入が完了すると、お客様には**「お支払いは店頭にてお願いいたします」**という案内が表示されます
- 同時に、`.env` の `ADMIN_USER_IDS` に登録されている**管理者全員に、
  「チケット購入・要会計」というLINE通知**が届きます(お客様のお名前・購入内容付き)。
  この通知をもとに、来店時に店頭で会計を行ってください
  (このボタンを押しただけで、実際の支払い処理や決済が自動的に行われるわけではありません)

### 来店確認(チケット消費)の方法

チケット会員から新規予約が入ると、担当スタッフへのLINE通知に
**「来店確認(チケット消費)」ボタン**が付きます。実際にお客様が来店したら、
このボタンをタップしてください。これでその予約が「来店確認済み」になり、
その予約の長さ(45分/60分)に応じたチケットが1枚消費されます。

## 月会費メンバーの予約制限(来月分は25日から・月あたりの回数制限)

月会費メンバーには、次の2つの制限をかけられます。

1. 「来月分の予約は、今月25日にならないと取れない」
2. 「1ヶ月あたりの予約回数の上限(人によって異なる回数を設定可能。繰り越しなし)」

(LINE公式アカウントマネージャーの「タグ」機能はMessaging APIから読み取れないため、
このBot自身でメンバーのLINEユーザーIDを管理する形にしています)

### 月会費メンバーの登録・回数設定方法(管理者のみ)

`.env` の `ADMIN_USER_IDS` に登録された管理者だけが使えます(チケット追加と同じ設定です)。

管理者がLINEで

```
月会費回数設定
```

と送ると、対話形式で設定できます。

1. 「1ヶ月あたりの予約回数を、数字だけで送ってください」→ 回数(例: `8`)を送る
2. 「対象のお客様のLINEユーザーIDを送ってください」→ お客様のIDを送る
3. 「月会費メンバーとして登録しました。月あたりの予約回数: ◯回」と表示されれば完了

すでに登録済みのお客様に対してもう一度実行すると、回数を更新できます
(この方法で設定した場合、1回のセッション時間は`BOOKING_DURATION_MINUTES`のデフォルト値になります)。

なお、`.env` の `MEMBER_LIST` で決め打ち登録する方法も引き続き使えますが、
その場合は回数の上限が設定されない(実質無制限)ため、回数制限をかけたい場合は
上記の「月会費回数設定」を使うことをおすすめします。

```
MEMBER_LIST=山田太郎:U1234...,鈴木花子:U5678...
```

### お客様自身によるコース選択(会員種別メニュー経由)

お客様が「会員種別」メニュー→「**月会費メンバー確認**」を選ぶと、以下の4コースから
選んでその場で登録できます(**初回登録の時だけ**)。

- 45分×月4回
- 45分×月6回
- 60分×月4回
- 60分×月6回

この方法で登録すると、回数だけでなく**1回のセッション時間(45分/60分)も
そのお客様専用の設定として保存され**、予約時にその時間で自動的に枠が計算されます
(チケット会員と同様、予約のたびに時間を選ぶ必要はありません)。

**一度登録すると、お客様自身ではコースを変更できません。**
登録済みのお客様が再度「月会費メンバー確認」を押すと、コース選択ではなく
現在のコース内容(時間・回数)が表示されるだけになります。
コースの変更は、管理者が「月会費回数設定」で行ってください
(この方法で回数を変更した場合、セッション時間は変更されず既存の設定のまま維持されます)。

### 月あたりの回数制限のルール(繰り越しなし)

- 回数は**カレンダー月(1日〜月末)ごとにリセット**されます
- 使わなかった回数を翌月に繰り越すことはできません
  (例: 月8回の設定で、今月3回しか使わなくても、来月は8回からのスタートです)
- その月の予約件数(来店確認の有無を問わず、確定している予約の件数)が回数に達すると、
  それ以上の新規予約はできなくなります
- 回数が設定されていない(`monthlyQuota`が0の)メンバーは、そのままだと1件も予約できません。
  必ず「月会費回数設定」で回数を設定してください

### 予約可能な日付のルール（通常会員25日・プラチナ会員18日）

- 通常会員は25日10:00、プラチナ会員は18日10:00より前の場合、
  「今月末」までしか予約できません
  (来月分はまだ選べません)
- 解禁時刻以降は、`MAX_DAYS_AHEAD`が30日でも**翌月末まで**予約できます
- 解禁日と時刻は、次の環境変数で変更できます

  ```
  MEMBER_NEXT_MONTH_OPEN_DAY=25
  PLATINUM_NEXT_MONTH_OPEN_DAY=18
  MEMBER_NEXT_MONTH_OPEN_HOUR=10
  ```

- 会員以外のお客様(ビジター等)には、これらの制限は一切かかりません(今まで通り予約可能)

## リッチメニュー(タップだけで操作できるメニュー)の作成

このBotは、他の通常のやり取り(スタッフとの個別チャットなど)を妨げないよう、
決まった文字(合言葉)や、決まったpostbackアクションが送られてきた時だけ反応する仕様です。

**現在の構成は、LINE Official Account Managerの画面では作れない「postbackアクション」
(タップしてもトーク画面に文字が表示されない、内部的な操作)を使っているため、
付属のスクリプトでMessaging APIを直接呼び出して作成します。**

### リッチメニューの構成(画像は6分割)

| 区画 | 内容 |
|---|---|
| 左上 | 入会申込(外部リンク) |
| 中央上 | メニュー(タップすると「予約」「予約確認」「会員種別」の3択が出る) |
| 右上 | Instagram(元住吉店) |
| 左下 | 月回数申込(外部リンク) |
| 中央下 | kaloko(フィットネスカルテサービス) |
| 右下 | Instagram(自由が丘店) |

リンク先や区画の内容を変えたい場合は、`scripts/setupRichMenu.js` の
`richMenuBody.areas` の部分を書き換えてください。

### 作成・更新手順

1. リッチメニュー用の画像(2500×1686px、6分割のデザイン)を用意する
   (`richmenu_final.jpg` として同梱しています。差し替えたい場合は同じサイズで作り直してください)
2. ターミナルでプロジェクトフォルダに移動し、以下を実行する

   ```bash
   node scripts/setupRichMenu.js richmenu_final.jpg
   ```

3. 「✅ すべて完了しました」と表示されれば成功です。LINEアプリでトーク画面を
   開き直すと、新しいリッチメニューが反映されます
4. 内容を変更したい場合は、`scripts/setupRichMenu.js` を編集してから、
   もう一度同じコマンドを実行してください(古いリッチメニューは自動的に削除されます)

### 「メニュー」ボタンでできること

中央上の「メニュー」をタップすると、「予約」「予約確認」「会員種別」の3つの選択肢が
(お客様側の発言としては何も表示されずに)表示されます。

- **予約**: 店舗選択からの新規予約
- **予約確認**: 予約の一覧表示・変更・キャンセル
- **会員種別**: 現在の会員種別確認、LINEユーザーID確認、会員種別の登録

「会員種別」を選ぶと、現在の種別(月会費メンバー/チケット会員/ビジター)と、
チケット会員の場合は残数が表示され、以下のボタンが続けて表示されます。

- **LINEユーザーID確認**: 「ID確認」と同じ内容が返信されます
- **月会費メンバーになる**: お客様自身が月会費メンバーとして登録されます
- **チケット会員になる**: お客様自身がチケット会員として登録されます(残数は0のまま。
  実際のチケット購入・枚数の付与は、来店時に管理者が「チケット追加」で行ってください)

お客様が自分で会員種別を選べる仕組みのため、**実際の入会・支払い手続きは
別途店舗側で行った上で**、このメニューで登録してもらう運用を想定しています
(登録するだけで自動的に料金が発生したり、支払い確認が行われたりはしません)。

### テキストの合言葉も引き続き使えます

リッチメニューのタップに加えて、「予約」「予約確認」「会員種別」とLINEで直接
入力しても、今まで通り同じ機能が使えます(どちらの方法でも動作は同じです)。

### 文言を変更したい場合

`src/index.js` の一番上にある各キーワード定数を書き換えてください。

```js
const RESERVATION_KEYWORD = '予約';
const CHECK_BOOKINGS_KEYWORD = '予約確認';
const MEMBER_MENU_KEYWORD = '会員種別';
```

(postbackアクションのdata文字列である`action=menu_reservation`等は変更不要です)

## イレギュラーな休み(スタッフが急に休みたい時)

シフトはコード上で固定されていますが、体調不良などで急に休みたい場合は、
**そのスタッフのGoogleカレンダーに、その日1日分の「終日予定」を1つ入れるだけ**で、
その日はそのスタッフの予約を丸ごと受け付けないようにできます。

- 終日予定のタイトルは、デフォルトで「**NG**」という文字を含んでいれば認識されます
  (`.env` の `FULL_DAY_BLOCK_KEYWORD` で変更可能。例: `FULL_DAY_BLOCK_KEYWORD=休み`)
- この予定が入っている日は、お客様がスタッフを選ぶ一覧にそのスタッフが表示されなくなります
  (シフト自体を消す必要はありません)
- 既に確定している予約がある場合、この仕組みは**新規予約を防ぐだけ**なので、
  既存の予約について別途お客様への連絡が必要な点にご注意ください

## 予約の変更・キャンセル

お客様がLINEで

```
予約確認
```

と送ると、ご自身の予約一覧(店舗・スタッフ・日時)が表示され、それぞれに
「変更する」「キャンセルする」ボタンが付きます。

- **変更**: 店舗・日付・スタッフ・時間を選び直すと、古い予約はカレンダーから削除され、
  新しい予約が登録されます。お名前は元の予約のものがそのまま引き継がれます
  (再入力は不要)。担当スタッフが変わった場合は、旧担当に「キャンセル通知」、
  新担当に「新規予約通知」がそれぞれ届きます。
- **キャンセル**: 最終確認(はい/いいえ)を挟んでから、カレンダーの予定を削除します。

**当日の予約は変更・キャンセルを受け付けません。** 予約一覧にボタンが表示されず、
「本日のご予約は変更・キャンセルを承っておりません」という案内のみが表示されます
(サーバー側でも同様のチェックを行っているため、当日中に無理に操作しようとしてもブロックされます)。

## 予約データはどこに保存されるか

`data/bookings.json` というファイルに、予約1件ごとの情報(お客様のLINEユーザーID、
店舗・スタッフ・日時・お名前・Googleカレンダーのイベント ID など)が保存されます。
「予約確認」で表示する一覧や、変更・キャンセル時の照合はこのファイルを参照しています。

## 予約時間の長さ設定

`.env` で1回の予約の長さを設定できます。

```
BOOKING_DURATION_MINUTES=60
```

デフォルトは60分です(月会費メンバー・チケット会員はそれぞれのコースの長さが優先されます)。

**予約の開始時刻は、常に「00分(時間ちょうど)」のみになります。**
(例: 9:00, 10:00, 11:00... であり、9:30や10:45のような開始時刻は候補に出ません)
これは、45分コースであっても60分コースであっても、開始時刻をキリの良い時間に
揃えるための仕様です。

## お客様への予約確認・スタッフへの通知の仕組み

- お客様が開始時刻を選んだ後、Botが「お名前をフルネームで教えてください」と尋ねます
  (同姓同名対策と、Googleカレンダー直接入力との名前照合の精度を上げるため、
  フルネームでの入力をお願いする案内文にしています。ただし入力自体のチェックは行っておらず、
  苗字だけなど1語だけの入力でもそのまま受け付けます)
- お客様がお名前を送ると、そのテキストがそのまま予約者名として使われます
  (この時点でのお客様の入力は「予約の名前入力待ち」の状態として、
  サーバーのメモリ上に一時保存されます。**サーバーを再起動するとこの状態は失われる**ため、
  お名前の入力待ちのままサーバーを再起動すると、その予約はやり直しになります)
- 予約が確定すると、Google Calendar APIでスタッフのカレンダーに
  「【予約】お客様名様」という予定が作成されます
- 同時に、担当スタッフのLINEユーザーIDが設定されていれば、
  そのスタッフに予約内容がLINEでプッシュ通知されます

## Googleカレンダーに直接入力された予約も拾う(名前照合)

お客様が「予約」または「予約確認」と送るたびに、Botは裏側で以下を行います。

1. そのお客様が**過去にLINE経由で予約した時に使ったお名前**を思い出す
2. 全スタッフのGoogleカレンダーを、そのお名前で検索する
3. まだ把握していない(LINE経由で登録した記録がない)予定が見つかったら、
   「お電話・店頭等でのご予約」として予約一覧に追加する

これにより、スタッフがGoogleカレンダーに直接入力した予約(電話予約や来店時の直接入力など)も、
お客様がLINEで「予約確認」をすれば一覧に表示され、変更・キャンセルもできるようになります。

### 注意点(名前照合の限界)

- **同姓同名**の別人がいた場合、他人の予定を誤って拾ってしまう可能性があります
- **LINE経由で一度も予約したことがないお客様**は、照合できる「お手本のお名前」がまだないため、
  この仕組みの対象になりません(初回はLINE経由で1回予約してもらう必要があります)
- 表記ゆれ(「太郎」と「たろう」など)があると一致しません。カレンダーに入力する際は、
  お客様がLINEで入力したお名前とできるだけ同じ表記にすることをおすすめします
- 店舗名は、その日のシフト表からスタッフを逆引きして自動判定しています。
  1人のスタッフが同じ日に複数店舗のシフトに入っている場合(通常は想定していません)、
  店舗の判定が不正確になることがあります

## 予約データの永続化について(重要)

- お名前の入力待ち状態は、サーバーの**メモリ上(変数)**に保持しています。
  そのため、お名前の入力待ちのままサーバーを再起動すると、その予約はやり直しになります。
- 確定した予約情報自体は `data/bookings.json` という**ファイル**に保存されるため、
  サーバーを再起動しても「予約確認」による一覧表示・変更・キャンセルは引き続き機能します。
- ただし、Cloud Runなど**ディスクが永続化されないサーバーレス環境**にデプロイする場合、
  再デプロイやインスタンスの入れ替わりのたびに `data/bookings.json` の中身が失われます。
  本格運用する場合は、Redisやデータベースなど外部の永続的なストレージに
  置き換えることを推奨します(`src/bookingStore.js` が該当箇所です)。

## カスタマイズポイント

- `src/shiftSchedule.js`: 店舗一覧・固定シフトパターン
- `src/config.js`: スタッフのカレンダーID・終日勤務時の時間帯・選択可能日数・タイムゾーンなど
- `src/calendarService.js`: 空き時間の計算ロジック
- `src/lineService.js`: 返信メッセージの見た目(Flex Messageのデザインなど)

## 会議室など、複数リソースの「全員が空いている時間」を見たい場合

`calendarService.js` の `getAvailableSlots` を、
`items` に複数のカレンダーIDを渡す形に拡張してください。
`freebusy.query` は複数カレンダーを一度に問い合わせでき、
レスポンスの `res.data.calendars` にカレンダーIDごとの busy 配列が入ります。
それぞれのbusyを合算してから空き時間を計算すれば、
「全員(全リソース)が空いている時間」を出せます。

## 注意事項

- このBotは「予定の有無」のみで空き/埋まりを判定します。
  終日予定やタイトルの内容までは考慮しません。
- シフトは固定パターンとしてコードに直接書かれています。
  祝日対応や単発の休みなど、例外的なシフト変更をしたい場合は、
  `getShiftsForDate` にその日だけの特例ルールを追加するか、
  例外日だけ別途手動で対応することをおすすめします。
